## 💭 Пара мыслей

<details>
<summary><b>Почему Rust, а не C++ для новых сервисов?</b></summary>

Обе задачи решаемы, но Rust даёт бесплатную проверку инвариантов компилятором и
предсказуемое время отклика без ручного управления памятью. C++ оставляю там, где нужен
прямой доступ к железу, есть готовая кодовая база или важна скорость сборки.
</details>

<details>
<summary><b>Как я отношусь к микросервисам</b></summary>

Сначала — один сервис с честными границами модулей. Дробить имеет смысл, когда есть
измеримая причина: разные требования к масштабированию, отдельные команды или модель
безопасности. Иначе это та же архитектура, просто с сетью внутри.
</details>

<details>
<summary><b>Что должно быть в каждом моём PR</b></summary>

Тест, который падал бы без изменений. Сообщение об ошибке, по которому понятно, что делать.
Бенчмарк, если менялась производительность. И ни одного «на потом оставлю».
</details>

<details>
<summary><b>Книга, которую перечитываю</b></summary>

«Designing Data-Intensive Applications» — второе издание, ради глав про консенсус
и распределённые транзакции, которые всё равно приходится читать дважды.
</details>
